A TOML file that sets only one key leaves the other defaults intact.\n\n## Keys and Nesting\n\nConfiguration is nested. A table in TOML becomes a nested dictionary. A nested key is addressed from the environment by joining the path with a double underscore and upper-casing it, under a prefix the caller chooses.\n\nExample with prefix `APP`:\n- TOML key: `server.port`\n- Environment variable: `APP__SERVER__PORT`\n\n## Coercion Rules\n\nEnvironment variables arrive as strings and must be coerced to match the type of the default already present for that key. Supported types:\n\n| Target type | Accepted string values (case-insensitive) |\n|-------------|-------------------------------------------|\n| `int`       | any valid integer literal (e.g. `42`, `-7`) |\n| `float`     | any valid float literal (e.g. `3.14`, `.5`, `1e3`) |\n| `bool`      | `true`, `false`, `yes`, `no`, `1`, `0` |\n| `str`       | any non-empty string (the value is used as-is) |\n\nA value that cannot be coerced is an error, not a silent fallback. An environment key with no corresponding default is also an error — it is almost always a typo, and silently accepting it is how a misspelled variable goes unnoticed.\n\n## Precedence Rules\n\n1. Start with the defaults dictionary.\n2. If a TOML file is provided and exists, parse it and merge into the defaults (deep merge, preserving missing keys).\n3. Read environment variables under the given prefix, coerce each value, and merge into the result (deep merge).\n\nIf any step fails (coercion error, missing default for an env key), raise `ConfigError` with a clear message naming the offending key and what was expected.\n\n## Error Reporting\n\nThe loader raises a single custom exception type `ConfigError` carrying a message that names the offending key and says what was expected. Several problems in one load should be reported together rather than one at a time, so the caller fixes them all in one pass.\n\n## Public API\n\n```python\ndef load(\n    defaults: dict,\n    toml_path: str | None = None,\n    env_prefix: str = \"\",\n    env: dict[str, str] | None = None,
) -> dict:\n    \"\"\"Merge defaults, optional TOML, and environment variables.\n\n    Returns the merged configuration dictionary.\n\n    Raises ConfigError if any value cannot be coerced or if an\n    environment variable has no corresponding default.\n\n    A missing TOML file is not an error; the layer is simply skipped.\n    \"\"\"\n```\n\n### Parameters\n\n- `defaults` – dict of base configuration (may contain nested dicts).\n- `toml_path` – optional path to a TOML file; if missing or unreadable, that layer is skipped.\n- `env_prefix` – string prefix used to build environment variable names (e.g. `APP`).\n- `env` – optional dict mapping environment variable names to string values; if omitted, `os.environ` is used.\n\n### Returns\n\nA single dict representing the merged configuration, with all values coerced to the types implied by the defaults.\n\n### Raises\n\n`ConfigError` – raised when:\n- An environment variable cannot be coerced to the expected type.\n- An environment variable is present but there is no corresponding default key (i.e. no path under that prefix in `defaults`).\n\n## Implementation Constraints\n\n- Python 3.10+ (uses `tomllib` from the standard library).\n- Standard library only.\n- Keep the module under about 150 lines.\n- Ship comprehensive tests covering:\n  - Precedence order (defaults < TOML < env).\n  - Nested overrides.\n  - Every coercion type (int, float, bool, str).\n  - Both error cases (bad coercion, missing default).\n  - The missing-file case (should be silently ignored).\n\n## Design Decisions\n\n1. **Deep merge**: We use a recursive merge so that nested tables from TOML or env vars only override the matching subtree. This matches the spec’s statement that “a TOML file that sets only one key leaves the other defaults intact.”\n\n2. **Coercion based on defaults**: The target type is inferred from the default value. This ensures that if a user changes the default, the coercion rules adapt automatically.\n\n3. **Single exception type**: All configuration problems are reported via `ConfigError`. This keeps the API simple and allows callers to catch all errors in one place.\n\n4. **Environment mapping**: By allowing an optional `env` dict, tests can run without touching the real environment, and the module remains deterministic.\n\n5. **Missing TOML is not an error**: The spec explicitly says “a missing TOML file is not an error; the layer is simply skipped.” We therefore check for file existence before attempting to parse.\n\n## Testing Strategy (brief)\n\n- Use `pytest` with parametrized tests for each coercion type and error case.\n- Mock `os.environ` and file I/O where appropriate to keep tests isolated.\n- Include a test that verifies that an env variable with no default raises `ConfigError` with a clear message.\n- Verify that a missing TOML file results in the same output as if the file were absent.\n\n---\n\nThis design document captures the approach, public API, precedence rules, coercion rules, and error reporting strategy for `envcfg`.\n"}}
