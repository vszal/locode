```# Task Queue Implementation Plan

## Milestone 1: Define the overall architecture

### Task Queue Overview
The task queue library, `taskq`, will allow a single application to enqueue background work and process it reliably. It will use SQLite for storage and support multiple worker threads within the same process. The library will provide methods for enqueuing tasks, registering task handlers, and managing worker threads.

### Component Breakdown
- **Queue Class**: Manages the task queue, including enqueuing tasks, starting/stopping workers, and retrieving statistics.
- **Worker Threads**: Execute registered task handlers.
- **Database Layer**: Handles interactions with the SQLite database to store and retrieve tasks.
- **Error Handling**: Manages task retries and failures.
- **Observability**: Provides methods to retrieve task statistics.

### Data Flow Diagram
```
[Application] -> [Queue Class] -> [Database Layer] -> [Worker Threads] -> [Task Handlers]
```

1. **Application** enqueues tasks using the `Queue` class.
2. **Queue Class** stores tasks in the database.
3. **Worker Threads** claim tasks from the database and execute them using registered handlers.
4. **Task Handlers** process the tasks and return results.
5. **Queue Class** updates the database with the task status (success, failure, etc.).

```# Task Queue Database Schema Design

## Schema Design
The SQLite database will have one table, `tasks`, to store all task-related information.

### Table: tasks
- **id** (INTEGER PRIMARY KEY): Unique identifier for each task.
- **name** (TEXT NOT NULL): Name of the task handler.
- **payload** (TEXT NOT NULL): JSON-serializable payload for the task.
- **state** (TEXT NOT NULL): Current state of the task (pending, running, done, dead).
- **attempts** (INTEGER NOT NULL DEFAULT 0): Number of attempts made to execute the task.
- **max_attempts** (INTEGER NOT NULL): Maximum number of attempts allowed for the task.
- **run_at** (REAL NOT NULL): Unix timestamp when the task is eligible to run.
- **claimed_until** (REAL): Unix timestamp when the task claim expires (NULL if not running).
- **idempotency_key** (TEXT): Optional key to ensure idempotent enqueuing.
- **last_error** (TEXT): Last error message if the task failed.
- **created_at** (REAL NOT NULL): Unix timestamp when the task was created.

## Indexes
- **(state, run_at)**: For efficient selection of eligible tasks.
- **idempotency_key** (partial UNIQUE): Ensures idempotent enqueuing by restricting the key to states pending and running.

## Database Configuration
- **WAL Mode**: Enable Write-Ahead Logging for better concurrency.
- **busy_timeout**: Set a timeout to handle busy database errors gracefully.
