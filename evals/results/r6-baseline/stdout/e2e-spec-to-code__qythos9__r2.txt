## Overview

`envcfg` assembles a single configuration dictionary from three layers:
1. **Defaults** – a plain dict supplied by the caller.
2. **TOML file** – parsed with `tomllib`, nested tables become nested dicts.
3. **Environment variables** – highest priority, read under a caller‑chosen prefix.

Later layers override earlier ones key‑by‑key, so a TOML file that sets only one key leaves the other defaults intact.

## Public API

```python
from envcfg import EnvConfigError, load

def load(
    defaults: dict,
    toml_path: str | None = None,
    env_prefix: str = "APP",
    env: dict[str, str] | None = None,
) -> dict:
    """
    Merge defaults, optional TOML, and environment variables.
    
    - `defaults`: required dict of base values.
    - `toml_path`: optional path to a TOML file; missing file is silently skipped.
    - `env_prefix`: prefix for environment variables (e.g. "APP" → APP__SERVER__PORT).
    - `env`: optional dict mapping env names to strings; if None, `os.environ` is used.
    
    Returns the merged dict. Raises `EnvConfigError` if any value is invalid.
    """
```

There is exactly one exception class: `EnvConfigError`.

## Precedence Rules

For each key in the final configuration:

1. Start with the value from `defaults`.
2. If a TOML file is provided and contains that key, replace with the TOML value.
3. If an environment variable exists (under `env_prefix`), replace with the coerced value.

If a key appears in `defaults` but not in TOML or env, the default stands. If a key appears in TOML or env but not in `defaults`, that is an error (see below).

## Coercion Rules

Environment variables are strings and must be coerced to match the type of the default value for that key. Supported types: `int`, `float`, `bool`, `str`.

### Boolean
Accepts (case‑insensitive): `true`, `false`, `1`, `0`, `yes`, `no`.  
Anything else → `EnvConfigError`.

### Integer
Attempts `int(value)`. If it raises `ValueError`, → `EnvConfigError`.

### Float
Attempts `float(value)`. If it raises `ValueError`, → `EnvConfigError`.

### String
Passed through unchanged.

### Missing default
If an environment variable is present (under the prefix) but there is no corresponding key in `defaults`, that is an error → `EnvConfigError`. This prevents silently accepting typos.

### TOML values
TOML values are taken as‑is (they are already parsed by `tomllib`). No coercion is applied.

## Error Reporting

All errors are collected in a single `EnvConfigError` instance. The exception message is a newline‑separated list, each line containing:
- the offending key (using the `env_prefix` joined with `__` and uppercased),
- the expected type,
- a brief description (e.g., “invalid boolean”, “missing default”, “invalid integer”).

Example message:
```
APP__SERVER__PORT: invalid integer
APP__CACHE__SIZE: missing default
```

The caller can inspect `e.errors` (a list of `EnvError` dataclasses) if they need structured access.

## Implementation Constraints

- Python 3.10+ only.
- Standard library only (`tomllib`, `os`, `typing`).
- Keep `envcfg.py` under ~150 lines.
- Ship `test_envcfg.py` covering:
  - precedence order (defaults → TOML → env),
  - nested overrides,
  - every coercion type,
  - both error cases (invalid coercion, env key without default),
