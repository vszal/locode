# DESIGN.md — envcfg specification

## Overview

envcfg is a small Python module that assembles one configuration dictionary from three layers:
- **defaults** (lowest priority): a plain dict supplied by the caller
- **TOML file** (medium priority): parsed with `tomllib`; missing files are silently ignored
- **environment variables** (highest priority): read under a caller‑chosen prefix, with nested keys joined by `__` and uppercased

Later layers override earlier ones key‑by‑key, so a TOML file that sets only one key leaves the other defaults intact.

## Public API

```python
from envcfg import ConfigError, load

def load(
    defaults: dict,
    toml_path: str | None = None,
    prefix: str = "APP",
    env: dict[str, str] | None = None,
) -> dict:
    """
    Merge defaults, an optional TOML file, and environment variables.
    
    - defaults: required, plain dict
    - toml_path: optional path to a TOML file; if missing, that layer is skipped
    - prefix: string prefix for env vars (e.g. "APP")
    - env: optional dict mapping env var names to string values; if None,
      os.environ is used
    
    Returns the merged configuration dict.
    
    Raises ConfigError if any env var is invalid (wrong type or missing default).
    """
```

### Return value
- A plain `dict` with the final merged configuration.
- Nested tables are represented as nested dicts (e.g. `{"server": {"port": 8080}}`).

### Exceptions
- **ConfigError** – raised when an environment variable cannot be coerced to the expected type or when an env var is present but there is no corresponding default key.
  - `ConfigError(message: str)` – message should include the offending key path and the expected type.

## Precedence Rules

1. **Defaults** are always present (they are never overridden by missing env vars; missing env vars are errors).
2. **TOML** values override defaults for any keys that exist in the TOML file.
3. **Environment** values override both defaults and TOML for any keys that exist in the environment (after coercion).
4. If an env var is present but there is no matching default key, raise `ConfigError`.
5. If a TOML file is missing, simply skip that layer; do not raise an error.

## Coercion Rules

Environment variables are strings and must be coerced to match the type of the default value for that key. Supported types:

| Target type | Accepted string values (case‑insensitive) |
|-------------|--------------------------------------------|
| `int`       | any valid integer literal (e.g. `"42"`, `"-7"`) |
| `float`     | any valid float literal (e.g. `"3.14"`, `"-0.5"`) |
| `bool`      | `true`, `false`, `yes`, `no`, `1`, `0` |
| `str`       | any non‑empty string (the value is used as‑is) |

Coercion is strict:
- If the string cannot be parsed as the target type, raise `ConfigError`.
- Do **not** silently fallback to the default; an invalid env var is always an error.
- An env var with no corresponding default key is also an error (likely a typo).

## Error Reporting

- All errors are collected and reported together in a single `ConfigError` exception.
- The exception message should list each offending key and what was expected, e.g.:
  - `"key 'server.port': expected int, got 'abc'"`
  - `"key 'database.host': missing default (env var present)"`
- This allows the caller to fix all problems in one pass.

## Implementation Constraints

- Python 3.10+
- Standard library only (use `tomllib` for TOML parsing)
- Keep `envcfg.py` under ~150 lines
- Provide comprehensive tests covering:
  - precedence order
  - nested overrides
  - every coercion type
  - both error cases
  - missing TOML file case
```
