{"name": "write_file", "args": {"path": "DESIGN.md", "content": "# envcfg — Design Document\n\n## Overview\n\n`envcfg` is a layered configuration loader that merges three sources of settings:\n\n1. **Defaults** – a plain Python dict supplied by the caller (lowest priority)\n2. **TOML file** – parsed with the standard library’s `tomllib` (medium priority)\n3. **Environment variables** – read from `os.environ` (highest priority)\n\nLater layers override earlier ones on a per‑key basis. Missing TOML files are silently ignored.\n\n---\n\n## Public API\n\n### Function: `load_config`\n\n```python\ndef load_config(\n    defaults: dict[str, Any],\n    toml_path: str | None = None,\n    env_prefix: str = \"APP\",\n    env: Mapping[str, str] | None = None,
) -> dict[str, Any]:\n```\n\n**Parameters**\n\n| Name | Type | Description |\n|------|------|-------------|\
| `defaults` | `dict[str, Any]` | Base configuration. Keys may be nested (e.g. `\"server\": {\"port\": 8080}`). |\
| `toml_path` | `str | None` | Optional path to a TOML file. If omitted or missing, that layer is skipped. |\
| `env_prefix` | `str` | Prefix for environment variables. Nested keys are joined with `__` and upper‑cased. Example: `APP__SERVER__PORT`. |\
| `env` | `Mapping[str, str] | None` | Optional mapping of environment variables. If `None`, `os.environ` is used. |\n\n**Returns**\n\nA merged `dict[str, Any]` reflecting the final configuration after all layers have been applied.\n\n**Raises**\n\n`envcfg.Error` – a single exception that contains a list of all configuration problems (see *Error Reporting* below).\n\n---\n\n## Layer Precedence Rules\n\n1. **Defaults** are always present and form the baseline.\n2. **TOML** values are applied on top of defaults. If a TOML key does not exist in defaults, it is added; if it does exist, it replaces the default value.\n3. **Environment** values are applied last. They override both defaults and TOML values for the same key.\n\nAll overrides are *key‑by‑key*; a TOML file that defines only `server.port` will not affect `server.host`, which remains at its default.\n\n---\n\n## Environment Variable Naming\n\nNested configuration is flattened for environment variables using a double‑underscore separator and uppercase letters.\n\nGiven a prefix `APP` and a nested key `server.port`, the corresponding environment variable is:\n\n```\nAPP__SERVER__PORT
```\n\nGeneral rule: replace each `/` or `.` in the key path with `__`, then uppercase the whole string.\n\n---\n\n## Coercion Rules\n\nEnvironment variables are always strings. They must be coerced to match the type of the existing default (or TOML) value for that key. Supported target types and their accepted string forms are:\n\n| Target type | Accepted strings (case‑insensitive) |\
|-------------|--------------------------------------|\
| `int` | any valid integer literal (e.g. `\"42\"`, `\"-7\"`) |\
| `float` | any valid floating‑point literal (e.g. `\"3.14\"`, `\"1e3\"`) |\
| `bool` | `true`, `false`, `1`, `0`, `yes`, `no` |\
| `str` | any non‑empty string (no coercion needed) |\

If a string cannot be parsed into the required type, an error is raised (see *Error Reporting*). An environment variable that has **no corresponding default** (i.e., no key in the merged configuration after defaults+TOML) is also an error – we treat this as a likely typo rather than silently ignoring it.\n\n---\n\n## Error Reporting\n\nAll configuration problems are collected into a single `envcfg.Error` exception. The exception carries a list of error messages, each formatted as:\n\n```\n<key>: expected <type>, got \"<value>\" (invalid)\n```\n\nor for missing keys:\n\n```\n<key>: no default provided\n```\n\nThe caller can inspect `e.errors` to see all issues at once, enabling a single‑pass fix of the configuration.\n\n---\n\n## Implementation Constraints\n\n- Python 3.10+ only\n- Standard library only (use `tomllib` for TOML parsing)\n- Keep the module under ~150 lines\n- Provide comprehensive tests covering:\n  - Layer precedence\n  - Nested overrides\n  - All coercion types\n  - Both error cases (invalid coercion, missing default)\n  - Missing TOML file (should be silently ignored)\n\n---\n\n## Design Decisions Rationale\n\n1. **Single exception with multiple messages** – avoids partial failure and gives the user a complete picture of what went wrong.\n2. **Strict coercion** – prevents silent data corruption; a typo in an env var will be caught immediately.\n3. **No default for env vars** – encourages explicit configuration and makes debugging easier.\n4. **Simple naming scheme** – double‑underscore + uppercase is easy to read and avoids conflicts with existing env vars.\n\n```\n"}
