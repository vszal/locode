# DESIGN.md — envcfg

## Overview

`envcfg` is a small Python module that merges three configuration layers:

1. **Defaults** – a dictionary supplied by the caller in code (lowest priority).
2. **TOML file** – parsed with the standard library’s `tomllib` (middle priority).
3. **Environment variables** – highest priority.

Later layers override earlier ones key‑by‑key, so a TOML file that sets only one key leaves the other defaults intact.

## Public API

```python
def load(
    defaults: dict,
    toml_path: str | None = None,
    prefix: str = "APP",
    env: os._Environ | None = None,
) -> dict:
    """
    Load and merge configuration.

    Parameters
    ----------
    defaults : dict
        Base configuration (lowest priority).
    toml_path : str | None
        Optional path to a TOML file. If missing, that layer is skipped.
    prefix : str
        Environment‑variable prefix. Nested keys are joined with `__` and
        uppercased. Example: `server__port` → `APP__SERVER__PORT`.
    env : os._Environ | None
        Environment mapping to read from. Defaults to `os.environ`.

    Returns
    -------
    dict
        Merged configuration with defaults at the bottom.

    Raises
    ------
    EnvCfgError
        If any environment variable is invalid (wrong type, missing default,
        or an unexpected key).
    """
```

## Precedence Rules

- **Defaults** are always present and form the base.
- **TOML** values are applied on top of defaults, key‑by‑key.
- **Environment** values are applied last, also key‑by‑key.
- If a TOML file is missing, that layer is simply omitted; no error is raised.
- If an environment variable is present but has no corresponding default key,
  `EnvCfgError` is raised (the key is likely a typo).

## Coercion Rules

Environment variables arrive as strings and must be coerced to match the type
of the default value for that key. Supported types and their accepted string
forms:

| Target type | Accepted strings (case‑insensitive) |
|-------------|--------------------------------------|
| `int`       | any valid decimal integer (e.g. `"42"`, `"-7"`) |
| `float`     | any valid decimal float (e.g. `"3.14"`, `"-0.5"`) |
| `bool`      | `true`, `false`, `1`, `0`, `yes`, `no` |
| `str`       | any non‑empty string (the value is used as‑is) |

Coercion is **strict**: if a string cannot be parsed into the expected type,
`EnvCfgError` is raised with a message naming the offending key and the expected
type.

## Error Reporting

All configuration problems are reported together via a single custom exception:

```python
class EnvCfgError(Exception):
    """Raised when an environment variable is invalid or unexpected."""
    pass
```

The exception message includes the key path and the expected type, e.g.:

- `"APP__SERVER__PORT: expected int, got 'abc'"`
- `"APP__LOG_LEVEL: unexpected key (no default)"`

## Implementation Notes

- Use only the standard library: `tomllib` for TOML parsing, `os` for environment
  access.
- Keep the module under ~150 lines.
- Test coverage must include:
  - Precedence order (defaults → TOML → env).
  - Nested overrides.
  - All coercion types (int, float, bool, str).
  - Both error cases (bad coercion, unexpected env key).
  - Missing TOML file (should be silently skipped).
