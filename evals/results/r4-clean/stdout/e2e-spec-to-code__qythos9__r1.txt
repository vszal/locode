# DESIGN.md — envcfg configuration loader

## Overview

`envcfg` assembles a single configuration dictionary from three layers:
1. **Defaults** – a plain dict supplied by the caller.
2. **TOML file** – parsed with the standard library `tomllib`.
3. **Environment variables** – read under a caller-chosen prefix.

Layers are merged key-by-key, with later layers overriding earlier ones. Missing
TOML files are silently ignored; missing environment keys are errors.

## Public API

```python
class EnvCfgError(Exception):
    """Raised when a configuration value cannot be coerced or an env key has
    no default."""
    pass

def load(
    defaults: dict,
    toml_path: str | None = None,
    env_prefix: str = "APP",
    env: dict[str, str] | None = None,
) -> dict:
    """
    Merge defaults, optional TOML, and environment variables.

    Parameters
    ----------
    defaults : dict
        Base configuration.
    toml_path : str | None
        Path to a TOML file. If None or missing, that layer is skipped.
    env_prefix : str
        Prefix for environment variables. Nested keys are joined with "__" and
        uppercased. Example: ``APP__SERVER__PORT`` maps to ``defaults["server"]["port"]``.
    env : dict[str, str] | None
        Mapping of environment variable names to strings. If None, ``os.environ``
        is used.

    Returns
    -------
    dict
        The merged configuration.

    Raises
    ------
    EnvCfgError
        If any environment variable cannot be coerced to the expected type, or
        if an environment variable is present but has no corresponding default.
    """
```

## Precedence Rules

- **Defaults** are the floor. Every key that appears in `defaults` is present in
  the final result.
- **TOML** overrides defaults for any matching key path.
- **Environment** overrides both defaults and TOML for any matching key path.
- If a key path exists in the environment but not in `defaults`, raise `EnvCfgError`.
- If a key path exists in `defaults` but not in the environment, keep the default.
- If a key path exists in `defaults` and the environment, coerce the env value to
  the type of the default and use it; otherwise raise `EnvCfgError`.

## Coercion Rules

Environment values are strings and must be coerced to the type of the default:

| Target type | Accepted strings (case‑insensitive) |
|-------------|--------------------------------------|
| `int`       | any valid integer literal (e.g. `"42"`, `"-7"`) |
| `float`     | any valid float literal (e.g. `"3.14"`, `"-0.5"`) |
| `bool`      | `"true"`, `"false"`, `"1"`, `"0"`, `"yes"`, `"no"` |
| `str`       | any non‑empty string (the value is used as‑is) |

Coercion is strict: if the string cannot be parsed as the target type, raise
`EnvCfgError`.

## Error Reporting

All configuration problems are collected and raised together as a single
`EnvCfgError`. The exception message lists each offending key path and the
expected type, e.g.:

```
EnvCfgError: invalid value for 'server.port' (expected int), invalid value for 'cache.enabled' (expected bool)
```

This allows the caller to fix all issues in one pass.

## Implementation Notes

- Use `tomllib.load()` for TOML parsing (Python 3.11+).
- Keep the module under ~150 lines.
- Tests must cover: precedence order, nested overrides, all coercion types,
  both error cases, and the missing‑file case.
