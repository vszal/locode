To implement the `total` function in `book_store.py`, I need to calculate the 
minimum cost of a basket of books by optimally grouping them into sets of 1, 2, 
3, 4, or 5 distinct books.



The key insight is that to minimize the total cost, we should maximize the 
number of larger groups (size 5, then 4, then 3, etc.) because the discount 
percentage increases with group size. However, simply taking the maximum 
possible size for each group greedily can be suboptimal. For example, if we have
counts `[3, 3, 3, 1, 1]`, taking a group of 5 leaves `[2, 2, 2, 0, 0]` which can
form a group of 3. But if we take a group of 4 first, we might be able to form 
more 4s or 5s later.



A robust approach is to use dynamic programming or a recursive search with 
memoization to find the optimal grouping. Given the small number of book types 
(5) and the fact that the basket size is usually manageable, we can represent 
the state by the counts of each book type. We can recursively try all possible 
valid group sizes (1-5) that can be formed from the current counts, and choose 
the one that leads to the minimum total cost.



Here is the plan:

1. Count the occurrences of each book (1-5).

2. Use a recursive function `min_cost(counts)` that takes a tuple of counts.

3. If all counts are 0, return 0.

4. Try every possible group size `k` from 5 down to 1.

5. For each `k`, check if it's possible to form a group of size `k` (i.e., at 
least `k` book types have count > 0).

6. If possible, generate all combinations of `k` distinct book types that have 
count > 0.

7. For each combination, decrement the counts for those books and recursively 
calculate the cost for the remaining books.

8. Add the cost of the current group (based on `k`) to the recursive result.

9. Keep track of the minimum cost found.

10. Return the minimum cost.



To optimize, I will use `functools.lru_cache` to memoize the results for each 
state (tuple of counts).
