{"name": "write_file", "args": {"path": "DESIGN.md", "content": "# taskq Design Document\n\n## Overview\n\n**taskq** is a durable, in-process task queue for Python 3.10+ using only the standard library. It provides a single SQLite database file that persists across process crashes, supports multiple worker threads within one process, and guarantees that no task is executed twice. The design prioritizes simplicity, correctness, and observability over extreme throughput.\n\n**Core approach:**\n- **Single SQLite database** with three tables: `tasks`, `task_claims`, and `task_stats`. All writes go through a single WAL-enabled connection to ensure atomicity.\n- **Claim-based execution**: Workers atomically claim a task via an `UPDATE` that sets `claimed_by` and `claimed_at`. The claim expires after 30 seconds; if not claimed within that window, the task becomes runnable again.\n- **Idempotent task identifiers**: Each task is uniquely identified by `(name, payload_hash, scheduled_at)`. This ensures that duplicate enqueues of the same logical job are treated as the same task.\n- **Retry policy**: Tasks are retried up to 5 times with exponential backoff (1s, 2s, 4s, 8s, 16s). After the fifth failure, the task is marked `dead` and set aside for human inspection.\n- **Crash recovery**: On startup, the system scans for unclaimed tasks (either never claimed or expired claims) and makes them runnable. No task can remain stuck forever.\n\nThis design satisfies all requirements: durability across crashes, thread-safe concurrent workers, no duplicate execution, bounded retries with backoff, and clear observability.\n\n## Public API\n\n### `taskq.init(db_path: str, max_workers: int = 4) -> None`\n\nInitialize the task queue. Creates the SQLite database and tables if they don't exist.\n\n**Parameters:**\n- `db_path`: Path to the SQLite database file (must end in `.db`).\n- `max_workers`: Maximum number of worker threads to spawn (default 4).\n\n**Returns:** Nothing.\n\n**Raises:** `FileExistsError` if `db_path` already exists and is not a valid SQLite database.\n\n**Thread safety:** Safe to call from any thread; subsequent calls are no-ops.\n\n### `taskq.enqueue(name: str, payload: dict, scheduled_at: datetime | None = None) -> str`\n\nEnqueue a new task.\n\n**Parameters:**\n- `name`: Task name (string, must not contain `:` or `\\n`).\n- `payload`: JSON-serializable dict containing task data.\n- `scheduled_at`: Optional datetime; if provided, the task will not be claimed until this time. If `None`, the task is available immediately.\n\n**Returns:** A unique task ID string (UUID v4).\n\n**Behavior:**\n- Computes a deterministic hash of `(name, payload)` to ensure idempotency.\n- Inserts a new row into `tasks` with `status = 'pending'`, `claimed_by = NULL`, `scheduled_at = scheduled_at`, and `retry_count = 0`.\n- Returns the generated UUID.\n\n**Thread safety:** Safe to call from any thread; concurrent calls will produce distinct task IDs.\n\n### `taskq.register_handler(name: str, handler: Callable[[dict], dict]) -> None`\n\nRegister a handler function for a task name.\n\n**Parameters:**\n- `name`: Task name (must match one of the names used in `enqueue`).\n- `handler`: A callable that takes a `dict` payload and returns a `dict` result.\n\n**Behavior:** Stores the handler in a thread-safe in-memory registry (a `dict` protected by a `threading.Lock`). Handlers are looked up by name when a task is claimed.\n\n**Raises:** `ValueError` if `name` is empty or contains invalid characters.\n\n**Thread safety:** Safe to call from any thread.\n\n### `taskq.run_workers(max_workers: int = None) -> None`\n\nStart the worker threads.\n\n**Parameters:**\n- `max_workers`: Optional override for the number of workers (defaults to `taskq.init`'s `max_workers`). If `None`, uses the stored value.\n\n**Behavior:**\n- Creates `max_workers` daemon threads, each running `worker_loop()`.\n- Workers continuously claim tasks, execute them, update status, and sleep briefly before claiming again.\n- Workers are joined on shutdown (via `taskq.shutdown()`).\n\n**Thread safety:** Only one `run_workers` call should be active at a time; concurrent calls will start additional threads (use `taskq.shutdown()` first).\n\n### `taskq.shutdown() -> None`\n\nStop all worker threads.\n\n**Behavior:** Sets a global flag that causes `worker_loop()` to exit cleanly. Waits for all threads to finish (up to 5 seconds) before returning.\n\n**Thread safety:** Safe to call from any thread.\n\n### `taskq.get_stats() -> dict`\n\nReturn current task statistics.\n\n**Returns:** A dict with keys:\n- `pending`: count of tasks with `status = 'pending'`.\n- `running`: count of tasks with `status = 'running'`.\n- `failed`: count of tasks with `status = 'failed'`.\n- `dead`: count of tasks with `status = 'dead'`.\n\n**Thread safety:** Safe to call from any thread.\n\n### `taskq.get_task(task_id: str) -> dict | None`\n\nRetrieve a task by its The task is then released (no claim is kept).\n- If the handler returns `\"retry\": false` (or raises an exception), the task is marked `status = 'failed'` and `last_error` is set. If `retry_count < 5`, the task is automatically re-claimed by the same thread after the backoff period (via a scheduled `SELECT` that finds tasks with `status = 'failed'` and `retry_count < 5` and sets `status = 'pending'` again). If `retry_count == 5`, the task is marked `status = 'dead'`.\n- The backoff is computed as `2 ** (retry_count - 1)` seconds.\n\n**Why this design?**\n- Exponential backoff is simple, effective, and avoids hammering failing dependencies.\n- A fixed limit of 5 retries balances durability with bounded resource usage.\n- The `retry` flag in the handler gives fine-grained control: transient failures can be retried, permanent failures can be marked dead.\n\n## Crash Recovery\n\n**Goal:** No task should remain stuck forever after a crash.\n\n**Mechanism:**\n1. **Claim expiry:** Every claim has an `expires_at = claimed_at + 30 seconds`. If a worker crashes before completing the task, the claim expires.\n2. **Startup scan:** On `taskq.init()`, we run a `SELECT` to find all tasks where `status = 'pending'` and either `claimed_by IS NULL` or `claimed_at < expires_at`. These are made runnable again (status remains `pending`, `claimed_by` is cleared).\n3. **Periodic cleanup:** A background thread (started by `run_workers`) runs every 10 seconds to scan for expired claims and re-claim those tasks.\n4. **Dead tasks:** Tasks that have failed 5 times are marked `status = 'dead'` and are never re-claimed. They are visible via `get_stats()` and `get_task_by_name()` for human inspection.\n\n**Guarantees:**\n- A task claimed by a thread that crashes will become runnable again after at most 30 seconds.\n- A task never claimed will be runnable immediately.\n- No task can be executed twice (the `payload_hash` ensures idempotency).\n\n## Failure Modes and Handling\n\n| Failure mode                              | How it manifests                              | How the design handles it                                   |\n|------------------------------------------|----------------------------------------------|------------------------------------------------------------|\
| **Process killed mid-run**              | Worker thread dies, task remains claimed     | Claim expires after 30s; task becomes runnable again      |\
| **Handler raises exception**            | Task marked `failed`, `retry_count` bumped   | If `retry_count < 5`, task is re-claimed after backoff; else marked `dead` |\
| **Handler returns `retry: true`**      | Task re-queued with backoff                 | Same as above                                              |\
| **Duplicate enqueue of same payload**   | Two rows with same `payload_hash`           | Both are treated as the same logical task; only one will be claimed (the other will be ignored) |\
| **Race between two callers enqueuing** | Two tasks created with same `name` and `payload` | Both get unique UUIDs; they are idempotent, so running both has no side effect |\
| **Worker thread crashes**               | No task is stuck forever                     | Claim expiry + startup scan ensures recovery               |\
| **Disk full / DB corruption**           | `sqlite3.OperationalError`                  | The `init()` call will raise; the caller must handle it (e.g., delete the DB and retry) |\
| **Network partition (not applicable)** | N/A                                          | N/A                                                         |\
| **Memory exhaustion**                   | OOM killer kills process                    | All tasks are persisted to disk; they will be recovered on restart |\
| **Handler takes too long**             | Task remains `running` for a long time      | No timeout; the task will eventually be claimed again after expiry if the worker crashes |\
