```DESIGN.md

envcfg — layered configuration loading

Overview
envcfg assembles a single configuration dictionary from three layers:
- defaults (dict) — lowest priority
- TOML file (path, optional) — medium priority
- environment variables (prefix, optional) — highest priority

Later layers override earlier ones key-by-key. A TOML file that sets only one key leaves the other defaults intact.

Public API
envcfg.load(defaults: dict, toml_path: str | None = None, prefix: str = "APP", env: dict | None = None) -> dict
- defaults: dict of nested config values (will be deep-copied)
- toml_path: path to a TOML file; missing file is silently skipped
- prefix: env prefix for nested keys (e.g. prefix="APP" → APP__SERVER__PORT)
- env: dict of env vars to read from (defaults to os.environ)
- returns: merged dict with same nesting as defaults

EnvcfgError
Raised when:
- an env var cannot be coerced to the expected type for its key, or
- an env var is present but has no corresponding key in defaults (possible typo).

Precedence rules
1. defaults are copied into the result.
2. TOML values are merged into the result (deep merge).
3. env values are merged into the result (deep merge).
At each merge step, later values overwrite earlier ones for the same key.

Coercion rules
Env vars are strings and must be coerced to match the type of the existing default for that key. Supported types: int, float, bool, str.

- int: string must be a valid integer (e.g. "42", "-7").
- float: string must be a valid float (e.g. "3.14", "-0.0").
- bool: accepts "true"/"false" (case-insensitive), "1"/"0", "yes"/"no" (case-insensitive).
- str: any string is valid.

Coercion errors are envcfgError with message "<key>: expected <type>, got '<value>'".

Env-only keys error: if an env key maps to a path that does not exist in defaults, envcfgError with message "<key>: no default for env key".

Nested key naming
Nested keys are joined with "__" and uppercased. With prefix APP, the env key APP__SERVER__PORT corresponds to the nested key {"server": {"port": ...}}.

Error reporting
envcfg.load raises envcfgError. Multiple problems are aggregated into a single exception with a message listing all errors, one per line.```tool
