{"name": "write_file", "args": {"path": "DESIGN.md", "content": "# envcfg — Design Document\n\n## Overview\n\n`envcfg` is a small Python module that assembles a single configuration dictionary from three layers:\n\n1. **Defaults** – a dictionary supplied by the caller in code (lowest priority)\n2. **TOML file** – values parsed from an optional TOML configuration file (medium priority)\n3. **Environment variables** – values read from the environment (highest priority)\n\nLater layers override earlier ones key-by-key. A TOML file that sets only one key leaves all other defaults intact.\n\n## Public API\n\n### Function: `load_config`\n\n```python\ndef load_config(\n    defaults: dict,\n    toml_path: str | None = None,\n    env_prefix: str = \"APP\",\n    env: dict[str, str] | None = None\n) -> dict:\n    \"\"\"\n    Load and merge configuration from three sources.\n\n    Args:\n        defaults: Dictionary of default values (lowest priority).\n        toml_path: Optional path to a TOML file. If missing, this layer is skipped.\n        env_prefix: Prefix for environment variable names. Nested keys are joined with \"__\" and uppercased.\n        env: Optional mapping of environment variable names to string values. If None, os.environ is used.\n\n    Returns:\n        Merged configuration dictionary with defaults at the bottom, TOML in the middle, and env vars on top.\n\n    Raises:\n        EnvCfgError: If an environment variable is present but has no corresponding default, or if coercion fails.\n    \"\"\"\n```\n\n### Exception: `EnvCfgError`\n\n```python\nclass EnvCfgError(Exception):\n    \"\"\"Raised when an environment variable cannot be coerced to the expected type, or when an env var has no default.\"\"\"\n    pass\n```\n\n## Precedence Rules\n\n- **Defaults** are always present and form the base configuration.\n- **TOML** values override defaults for any keys they define. If a TOML file is missing, no error is raised; that layer is simply skipped.\n- **Environment variables** override both defaults and TOML values.\n- For nested keys, the environment variable name is constructed by:\n  1. Starting with `env_prefix`.\n  2. For each level of nesting, appending `__` and uppercasing the key name.\n  3. Example: with `env_prefix=\"APP\"`, the nested key `server.port` becomes `APP__SERVER__PORT`.\n\n## Coercion Rules\n\nEnvironment variables arrive as strings and must be coerced to match the type of the default value for that key.\n\nSupported types and their coercion rules:\n\n| Default type | Accepted string values (case-insensitive) |\n|--------------|-------------------------------------------|\n| `int`        | any valid integer literal (e.g., `\"42\"`, `\"-7\"`) |\n| `float`      | any valid float literal (e.g., `\"3.14\"`, `\"-0.5\"`) |\n| `bool`       | `true`, `false`, `yes`, `no`, `1`, `0` |\n| `str`        | any non-empty string (the value is used as-is) |\n\nIf a string cannot be coerced to the expected type, an `EnvCfgError` is raised with a message that names the offending key and states what was expected.\n\n## Error Reporting\n\n- The loader raises a single `EnvCfgError` exception.\n- The exception message includes the problematic key and the expected type, e.g.:\n  - `\"Key 'server.port' expected an integer but got 'abc'\"`\n  - `\"Key 'debug' has no default value\"`\n- Multiple problems in one load are reported together (the caller fixes them all in one pass).\n- A missing TOML file is **not** an error; it is simply skipped.\n- An environment variable with no corresponding default is an error (almost always a typo).\n\n## Implementation Constraints\n\n- Python 3.10+ only.\n- Standard library only – use `tomllib` for TOML parsing.\n- Keep the module under ~150 lines.\n- Ship comprehensive tests covering:\n  - Precedence order (defaults < TOML < env).\n  - Nested overrides.\n  - Every coercion type (int, float, bool, str).\n  - Both error cases (bad coercion, missing default).\n  - The missing-file case.\n\n## Design Rationale\n\n- **Single exception type**: simplifies error handling and ensures callers can catch all configuration problems uniformly.\n- **Explicit coercion**: prevents silent fallbacks that hide typos; the caller must fix invalid env vars.\n- **Optional TOML**: allows projects to ship a config file without forcing it; missing files are benign.\n- **Nested env var naming**: follows a common convention (double underscore, uppercase) and keeps the API simple.\n- **Defaults always present**: ensures a valid configuration is always returned, even if no env vars or TOML are provided.\n", "overwrite": true}}
