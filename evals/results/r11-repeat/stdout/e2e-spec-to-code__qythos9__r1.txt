{"name": "write_file", "args": {"path": "DESIGN.md", "content": "# envcfg — Design Document\n\n## Overview\n\n`envcfg` is a small Python module that assembles a single configuration dictionary from three layers:\n\n1. **Defaults** – a dictionary supplied by the caller in code (lowest priority)\n2. **TOML file** – values parsed from an optional TOML configuration file (medium priority)\n3. **Environment variables** – values read from the environment (highest priority)\n\nLater layers override earlier ones key-by-key. A TOML file that sets only one key leaves all other defaults intact.\n\n## Public API\n\n### Function: `load_config`\n\n```python\ndef load_config(\n    defaults: dict,\n    toml_path: str | None = None,\n    env_prefix: str = \"APP\",\n    env: dict[str, str] | None = None\n) -> dict:\n    \"\"\"\n    Load and merge configuration from three sources.\n\n    Args:\n        defaults: Dictionary of default values (lowest priority).\n        toml_path: Optional path to a TOML file. If missing, this layer is skipped.\n        env_prefix: Prefix for environment variable names. Nested keys are joined with \"__\" and uppercased.\n        env: Optional mapping of environment variable names to string values. If None, os.environ is used.\n\n    Returns:\n        Merged configuration dictionary with defaults at the bottom, TOML in the middle, and env vars on top.\n\n    Raises:\n        EnvCfgError: If an environment variable is present but has no corresponding default, or if coercion fails.\n    \"\"\"\n```\n\n### Exception: `EnvCfgError`\n\n```python\nclass EnvCfgError(Exception):\n    \"\"\"Raised when an environment variable cannot be coerced to the expected type, or when an env var has no default.\"\"\"\n    pass\n```\n\n## Precedence Rules\n\n- **Defaults** are always present and form the base configuration.\n- **TOML** values override defaults for any keys they define. Missing TOML files are silently ignored.\n- **Environment variables** override both defaults and TOML values.\n- For nested keys, the environment variable name is constructed by:\n  1. Starting with `env_prefix`\n  2. For each level of nesting, appending `__` + the key name in uppercase\n  \n  Example: `APP__SERVER__PORT` corresponds to `defaults[\"server\"][\"port\"]`.\n\n## Coercion Rules\n\nEnvironment variables are strings and must be coerced to match the type of the existing default value for that key. Supported types:\n\n| Target Type | Accepted String Values (case-insensitive) |\n|-------------|-------------------------------------------|\n| `int`       | any valid integer literal (e.g., `42`, `-7`) |\n| `float`     | any valid float literal (e.g., `3.14`, `.5`, `1e3`) |\n| `bool`      | `true`, `false`, `yes`, `no`, `1`, `0` |\n| `str`       | any non-empty string (no coercion needed) |\n\nIf a string cannot be coerced to the expected type, `EnvCfgError` is raised with a message naming the offending key and the expected type.\n\n**Important:** An environment variable that has no corresponding default key is also an error — this is almost always a typo, and silently accepting it would hide misspellings.\n\n## Error Reporting\n\n- All errors are raised as a single `EnvCfgError` exception.\n- The exception message includes a list of problematic keys and the expected type for each.\n- This allows the caller to fix all issues in one pass rather than handling them one at a time.\n\n## Implementation Constraints\n\n- Python 3.10+ only\n- Standard library only — use `tomllib` for TOML parsing\n- Keep the module under ~150 lines\n- Ship comprehensive tests covering:\n  - Precedence order (defaults < TOML < env)\n  - Nested overrides\n  - Every coercion type (int, float, bool, str)\n  - Both error cases (coercion failure, missing default)\n  - Missing TOML file (should be silently skipped)\n\n## Design Rationale\n\n- **Single exception**: Consolidating errors into one exception prevents partial fixes and makes debugging easier.\n- **Explicit coercion**: Rather than silently falling back to defaults, we require the user to fix invalid env vars — this catches typos and misconfigurations early.\n- **No TOML file error**: A missing config file is not unusual; we treat it as “no override” rather than an error.\n- **Nested env var naming**: Using `__` and uppercase is a common convention (e.g., `DJANGO__DATABASE__HOST`) and keeps env var names readable while preserving hierarchy.\n"}
