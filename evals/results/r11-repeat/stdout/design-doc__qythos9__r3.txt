It provides a simple API for enqueuing background work, processing it with worker threads, and guaranteeing that no task is lost even if the process crashes. The design prioritizes correctness and simplicity over features: no distributed coordination, no priority queues, no cancellation, and no web UI. Workers claim tasks atomically via a database row lock, and the database enforces that only one worker can hold a claim at a time. Retries are implemented with exponential backoff, and tasks that exceed a retry limit are marked dead and logged for human inspection. The parameters are:\n\n- `max_retries`: maximum number of retry attempts (default 3).\n- `retry_base`: initial delay in seconds (default 1.0).\n- `retry_max`: maximum delay (default 60.0).\n\nWhen a task fails, its `retry_count` is incremented. The next attempt is scheduled after `min(retry_base * (2 ** retry_count), retry_max)` seconds. This is implemented by setting `scheduled_at` to the current time plus the computed delay. If a worker is killed (SIGKILL, power loss) before it calls `complete`, the task remains in `running` state with a stale `claimed_by`. A periodic cleanup job (or the worker itself) scans for tasks where `claimed_at` + `claim_timeout` < now and re-claims them (sets `state` back to `pending`, clears `claimed_by`). This ensures no task is permanently stuck.\n\n2. **Dead task purging**: Tasks that are `failed` beyond `max_retries` are marked `dead`. They are not re-queued.
