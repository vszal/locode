It provides a simple API for enqueueing background work, with built-in support for retries, scheduling, and crash recovery. The library uses a single SQLite database file for persistence and multiple worker threads within one process to handle tasks concurrently.\n\nThe core approach is to treat the SQLite database as the single source of truth. All state (pending, running, failed, dead tasks) is stored in tables with appropriate indexes for fast lookups. Workers claim tasks atomically using SQLite row-level locking, ensuring no two workers ever process the same task simultaneously. This ensures that no task remains stuck in `running` state after a crash.\n\nThe 30-second window is chosen as a balance between allowing short-lived tasks to complete and recovering quickly from crashes.
